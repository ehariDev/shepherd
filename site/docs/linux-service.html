Linux service (systemd)

Shepherd runs equally well as a plain systemd service — no Kubernetes required. This page targets RHEL 8/9 and compatible rebuilds (Rocky Linux, AlmaLinux, Oracle Linux); the unit itself is portable systemd and works unmodified on other distributions, but the package-manager and SELinux/firewalld steps below are RHEL-specific.

Download the server tarball from a release. It ships shepherd, shepherd-simulator, the systemd unit and both example config files under deploy/systemd/.

1. Create the service account

shell
useradd --system --no-create-home --shell /sbin/nologin shepherd

2. Install the binary

shell
install -o root -g root -m 0755 shepherd /usr/local/bin/shepherd
restorecon -v /usr/local/bin/shepherd

SELinux ports need no extra step here. Run from /usr/local/bin, Shepherd's process type is the generic unconfined_service_t, which may bind any port — unlike an httpd-labelled process, there is no semanage port -a to run. Confirm with ausearch -m AVC -ts recent after your first start; a clean result there is the actual proof, not this note.

3. Install Alloy

Stage 2 of pipeline validation execs the alloy binary. Without it, every validation reports skipped, not valid — silently weaker, not broken. Install it from Grafana's own repository:

shell
cat > /etc/yum.repos.d/grafana.repo <<'EOF'
[grafana]
name=grafana
baseurl=https://rpm.grafana.com
repo_gpgcheck=1
enabled=1
gpgcheck=1
gpgkey=https://rpm.grafana.com/gpg.key
EOF
dnf install -y alloy

Point validate.alloy_binary in shepherd.yaml at /usr/bin/alloy (dnf's default install path). Match the version to ALLOY_IMAGE/ALLOY_VERSION in the release's deploy/versions.env — Stage 2 is only meaningful against the same Alloy your fleet actually runs.

4. PostgreSQL 16

On RHEL 8/9, PostgreSQL ships as an AppStream module with several stream versions available side by side — pick 16 explicitly, since the module's own default is usually older:

shell
dnf module enable -y postgresql:16
dnf install -y postgresql-server
postgresql-setup --initdb
systemctl enable --now postgresql

RHEL 10 dropped AppStream modularity — there dnf install postgresql-server alone installs 16 directly, no module enable step. If you are on the PGDG repository instead of the distribution's own package, follow PostgreSQL's own RHEL instructions in place of the two commands above; everything from SHEPHERD_DATABASE_URL onward is unaffected either way.

Create the role and database, then set the connection string in shepherd.env (never in shepherd.yaml — see Configuration files below):

shell
sudo -u postgres psql -c "CREATE USER shepherd WITH PASSWORD '<choose-one>';"
sudo -u postgres psql -c "CREATE DATABASE shepherd OWNER shepherd;"

5. Certificates

RHEL's own PKI layout, which the shipped unit and example config both assume:

PathOwnerMode
/etc/pki/tls/certs/shepherd.crtroot:root0644
/etc/pki/tls/private/shepherd.keyroot:shepherd0640
shell
chown root:shepherd /etc/pki/tls/private/shepherd.key
chmod 640 /etc/pki/tls/private/shepherd.key
restorecon -Rv /etc/pki/tls

A certificate copied in from a home directory keeps user_home_t and will be denied even with the file permissions above correct — SELinux checks the type, not just the Unix mode bits. restorecon -Rv /etc/pki/tls after copying anything in relabels it to cert_t, the type /etc/pki/tls already carries by default.

6. Renewal

Shepherd's certificate hot-reload (polling every server.tls.reload_interval, default 30s, plus systemctl reload shepherd for an immediate one) means a renewal hook only needs to replace the files — no coordination with Shepherd's process beyond that.

certmonger (IdM/FreeIPA-issued certificates):

shell
getcert request -f /etc/pki/tls/certs/shepherd.crt -k /etc/pki/tls/private/shepherd.key \
  -C "systemctl reload shepherd"

certbot (Let's Encrypt or another ACME CA):

shell
certbot certonly --deploy-hook "systemctl reload shepherd" ...

Neither hook is strictly required: the poll alone picks up a renewed file within reload_interval, so a renewal tool with no hook support still works, just not instantly.

7. firewalld

shell
firewall-cmd --permanent --add-port=8443/tcp
firewall-cmd --reload

8. crypto-policies and FIPS

Go does not read RHEL's system-wide crypto-policies (update-crypto-policies). server.tls.min_version is Shepherd's own, independent control; the default, TLS 1.2, is already within RHEL's DEFAULT policy, so there is nothing to reconcile in the common case.

FIPS 140-3 mode is documented as untested, not unsupported. Go's native FIPS mode can be requested with Environment=GODEBUG=fips140=on in the unit, but this has not been validated end to end on a FIPS-enabled host. Treat it as a starting point for your own validation, not a claim.

9. Trust on collectors

A collector's Alloy needs to trust whatever issued Shepherd's certificate. Either trust it at the OS level, or point remotecfg at it directly — see Connect a collector for the tls_config block.

shell
# OS-level trust (private CA), on the collector host:
cp private-ca.pem /etc/pki/ca-trust/source/anchors/
update-ca-trust

10. Configuration files

Install both example files from the tarball's deploy/systemd/, filled in:

FileOwner / modeHolds
/etc/shepherd/shepherd.yamlroot:shepherd, 0640Everything non-secret — server.tls.*, validate.alloy_binary, and so on. See Configuration for the full key list.
/etc/shepherd/shepherd.envroot:shepherd, 0640SHEPHERD_DATABASE_URL, SHEPHERD_SECURITY_ENCRYPTION_KEY, SHEPHERD_BOOTSTRAP_ADMIN_PASSWORD — never in the YAML file.

11. Install and start the unit

shell
cp deploy/systemd/shepherd.service /etc/systemd/system/shepherd.service
systemctl daemon-reload
systemctl enable --now shepherd

ExecStartPre runs shepherd migrate up before every start, so the schema is always current before serve begins — the same ordering the Helm chart's migration Job gives you.

12. Verifying

shell
systemctl status shepherd
shepherd healthcheck --tls --insecure-skip-verify --addr localhost:8443
journalctl -u shepherd -f

# Certificate rotation without a restart:
systemctl reload shepherd
journalctl -u shepherd -n 5   # look for "SIGHUP: TLS certificate reloaded"

--insecure-skip-verify is for exactly this case — a localhost check against a certificate whose SAN is the public hostname, not localhost. Supply --ca-file instead once you have one, or omit both flags entirely and let the system trust store decide, the same as any other HTTPS client.
