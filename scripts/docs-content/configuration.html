Configuration

Shepherd is configured from environment variables (a Kubernetes Secret in a chart install, your shell in local development). Only two are required — the server refuses to start without them — and the rest matter only for the setups they name.

The secret Shepherd reads

In a chart install these are keys of the Kubernetes Secret the chart reads (shepherd-secrets by default, or override existingSecret). Running locally, they are plain environment variables.

KeyRequired?Description
SHEPHERD_DATABASE_URLYesPostgreSQL connection string
SHEPHERD_SECURITY_ENCRYPTION_KEYYesBase64-encoded 32-byte key encrypting stored credentials at rest. Keep it — a replacement key cannot decrypt what the old one wrote
SHEPHERD_BOOTSTRAP_ADMIN_PASSWORDRecommendedPassword for the administrator created on first boot. Read only while the users table is empty. Leave it unset and the account is created as admin/admin, which can do nothing until the password is changed
SHEPHERD_OIDC_CLIENT_SECRETChart-configured SSO onlyOmit it to configure SSO from the UI instead
SHEPHERD_GRAPH_CLIENT_SECRETEntra + Graph lookup onlyNot used by any other provider

See deploy/helm/shepherd/values.yaml for the full set of chart options, including networkPolicy and autoscaling. The chart has no user-seeding options of its own — the bootstrap admin above is the only account a fresh install creates. (shepherd dev seed, which additionally creates local editor/viewer accounts, is a dev-only CLI command outside the chart; see internal/cli/dev.go.)

Where these values come from is a separate decision: see Secrets for supplying them yourself or having them generated, and Database for the connection string.

The encryption key is not rotatable

Keep SHEPHERD_SECURITY_ENCRYPTION_KEY. It encrypts git credentials and the OIDC client secret at rest. A new key on the next boot cannot decrypt what the old one wrote, and Shepherd has no way to tell you which stored secret it has just lost — it simply fails to use them. Generate it once, store it where you store your other secrets, and back it up with them.

The first administrator

SHEPHERD_BOOTSTRAP_ADMIN_LOGIN and SHEPHERD_BOOTSTRAP_ADMIN_PASSWORD are read only while the users table is empty, on first boot. Set the password and the account is yours. Leave it unset and the account is created as admin/admin with a forced password change, which blocks every request except the change itself — so an unattended install cannot quietly sit on a default credential. After first boot, accounts are managed at Admin → Users; see Users and teams.

Native TLS (HTTPS)

Unset, Shepherd serves cleartext (h2c) on server.listen, unchanged from every release before TLS support existed. Set both cert_file and key_file and it serves HTTPS instead — there is no separate on/off flag. See Kubernetes for the chart's tls: block, which wires most of these for you from a Secret.

KeyEnv varDefaultDescription
server.tls.cert_fileSHEPHERD_SERVER_TLS_CERT_FILE—PEM certificate path. Both this and key_file must be set together, or neither
server.tls.key_fileSHEPHERD_SERVER_TLS_KEY_FILE—PEM private key path
server.tls.min_versionSHEPHERD_SERVER_TLS_MIN_VERSION1.21.2 or 1.3
server.tls.client_authSHEPHERD_SERVER_TLS_CLIENT_AUTHnonenone, request or require_and_verify (mTLS plumbing only — a presented client certificate is not mapped to any Shepherd identity)
server.tls.client_ca_fileSHEPHERD_SERVER_TLS_CLIENT_CA_FILE—PEM CA bundle verifying client certificates. Required when client_auth is not none
server.tls.reload_intervalSHEPHERD_SERVER_TLS_RELOAD_INTERVAL30sHow often the certificate files are polled for a rotation. 0 disables polling; a SIGHUP (systemctl reload) still forces one
server.tls.collector_ca_fileSHEPHERD_SERVER_TLS_COLLECTOR_CA_FILE—Opt-in: injects a tls_config into the beacon's served pipeline, so collectors trust a private CA. Unset leaves that rendered pipeline byte-identical to before TLS existed

A failed certificate reload never takes the listener down. Shepherd keeps serving the last good certificate, logs the failure, and counts it in shepherd_tls_cert_reloads_total{result="failure"} — shepherd_tls_cert_not_after_seconds is the currently-served certificate's expiry, for alerting before it actually runs out.

Single sign-on

One setting decides where SSO configuration comes from: oidc.issuer. Set it in your chart values and the chart owns SSO; leave it unset and an app admin configures a provider from the UI instead. Single sign-on covers both paths and what each one costs you.
